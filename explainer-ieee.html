1 · Standards that map to this project

IEEE standardWhat it governsWhere Health Quest complies
IEEE 7000™-2021
Ethical Concerns in System Design		 A model process for addressing ethical concerns during design — the flagship “ethics-by-design” standard. The ethics banner, consent-first location flow, PIN-code alternative, no-timer/no-streak mechanics and the “Why this rating” transparency principle are direct design artifacts of an ethics-first process.
IEEE 29148™-2018
Requirements Engineering		 Structuring software/system requirements specifications (SRS). This repository's SRS (README) is written as traceable requirement statements; every feature maps to a verifiable acceptance check.
IEEE 12207™-2017
Life-Cycle Processes		 Standard processes for developing and maintaining software. The project follows a simple, documented lifecycle: requirements → design → implementation (single-file app) → verification (checklist in README) → deployment (Vercel) → operation/maintenance roadmap.
IEEE 1012™-2016
Verification & Validation		 Asking “did we build the thing right?” and “did we build the right thing?”. README section 8 lists a V&V checklist (every expectation with a pass/fail test); markdown export/import round-trips the food database.
IEEE 730™-2014
Quality Assurance		 Planning and executing quality assurance for software. The score formula is single-sourced; all 20+ foods reuse the same 5-criteria engine so no value can be hand-tuned inconsistently.
IEEE 828™-2012
Configuration Management		 Managing versions, baseline and change control. Versioned app (v3.1), food database shipped inside the single file, and markdown import gives a human-readable configuration record.

2 · Why this matters to a judge (in 60 seconds)

  1. IEEE 7000 is the world's flagship answer to the exact harms this project confronts (Blue Whale, Pokémon Go). Health Quest implements its central idea: address ethical concerns during design, not after.
  2. IEEE 29148 + 12207 show the work is engineered, not improvised — requirements are traceable to live features.
  3. IEEE 1012 + 730 are proof it was verified — the README checklist doubles as the V&V record.
  4. The entire system is transparent by construction: every score, every venue rating, and the scoring formula itself is open and auditable.

3 · How the code maps to IEEE 7000 (ethics)

🧭 Consent-first location

geolocation.getCurrentPosition() is called only after an explicit button tap; the PIN-code path never touches location at all. Location is used once for a radius search and never persisted — compliance with privacy-by-design.

🧘 No-pressure mechanics

No timers, no streaks, no name-based leaderboards. A “wrong” answer is framed as a lesson. Filtered via the offline/online hint engine that never shames the user.

🔍 Transparency everywhere

Every food and venue has a “Why this rating” breakdown. The scoring formula is printed on the About page. This is direct application of the Michelin principle, formalised here as IEEE 7000 ethical traceability.

🔑 BYOK privacy

AI keys are stored in localStorage and sent only to the user's chosen provider. No backend, no accounts, no data collection — the strongest possible privacy posture for a web app.

5 · Submission configuration cheat-sheet

📄 Paper format

A4, 1-in margins, 10-pt Times New Roman, single column (student report) or IEEE two-column (conference). Title, author, affiliation, abstract < 250 words, keywords.

🔖 Keywords

health education; nutrition; transparency; ethics-by-design; web application; OpenStreetMap; privacy; K-12 EdTech.

🧾 Abstract (sample)

“Health Quest is an offline-first, framework-free web game that teaches school students to identify healthier food through a fully transparent Health Score. Built on IEEE 7000 ethics-by-design, it avoids pressure mechanics, respects location consent, and surfaces real nearby eateries from OpenStreetMap through a serverless proxy. The system costs ₹0 to run and stores no user data.”
